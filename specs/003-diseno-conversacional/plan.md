# Implementation Plan: Diseño Conversacional (Bloque 3)

**Branch**: `003-diseno-conversacional` | **Date**: 2026-10-08 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/003-diseno-conversacional/spec.md`

## Summary

Implementar el flujo conversacional en el frontend y los contratos de comunicación con el backend para satisfacer los requerimientos del Bloque 3: mensaje de bienvenida fijo con advertencias de alcance, flujo de consentimiento de datos ("Autorizo" / "No autorizo"), categorización de consultas, y acceso rápido a canales de emergencia. La arquitectura usa estado volátil en React para cumplir con las estrictas reglas de privacidad, y un endpoint rápido de Express para servir los contactos de emergencia sin invocar al LLM.

## Technical Context

**Language/Version**: TypeScript (Frontend: Next.js + React; Backend: Node + Express)

**Primary Dependencies**: React (hooks, Context), Next.js, Express

**Storage**: PostgreSQL (used by backend for contacts; frontend state is strictly volatile memory)

**Testing**: Jest, React Testing Library

**Target Platform**: Web (Responsive: Desktop & Mobile iframe)

**Project Type**: Fullstack Web Application (Frontend UI + Backend API)

**Performance Goals**: Emergency contacts must load in < 2 seconds.

**Constraints**: `autorizo` flag MUST control history payload. Text must NOT be stored in `localStorage`, cookies, or URL.

**Scale/Scope**: Conversational widget serving citizens of Envigado.
